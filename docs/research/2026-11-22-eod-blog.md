# Agent Blog as Echo of Dreams' blog

Status: **decided, planned as [M2b](../ROADMAP.md)** (owner, 2026-11-22: several writers, by invitation, on every
Agent Blog; EoD's comments kept through the widget; each post's history starts at the import). Researched 2026-11-22. The owner asked: *"look at EoD blog console. Reuse what makes sense, and think about
how we can use THIS instead of the current Blog Console."* The inventory of EoD's blog comes from its code at
`8c3312ca` (BLOG_SERVICE.md, BLOG_TOOL_PACK.md, `blogConsole/`, `BlogEndpoints.cs`, `BlogAuthorEndpoints.cs`,
`BlogSeoEndpoints.cs`, `named_pages`, `56a_blog_role_functions.sql`). Nothing here is decided.

## What EoD's blog is today

- **One React SPA** at blog.echoofdreams.eu: the reader (index, post, tag, category, author) and the author surface
  (`/_author`: TipTap editor with Markdown and preview, autosave, revision drawer, preview links, cover and gallery
  picture pickers, review queue, category admin). The post body is rendered in the browser; bots get OG tags through
  the cf-worker.
- **Posts are `named_pages` rows** (`page_kind = 'blog_post'`) with tags, hierarchical categories, JSONB revision
  snapshots (90-day sweep of unpinned), `publish_at` with `scheduled_by` (the rule Agent Blog lifted), RSS, Atom,
  sitemap, signed preview links.
- **Roles** (`users.blog_role`): contributor (drafts, submit for review), editor (publish, any post), admin (delete,
  categories, grant roles); rights ≥ 3 is admin; a 13–17 account has none.
- **Social, through EoD's platform:** comments and reactions are EoD's global systems (entity type 14, keyed by the post
  uuid; reactions 18+), creator cards with Follow and Tip, a notification bell, reports, the admin moderation tabs.
- **Agents:** the `blog_authoring` pack, 11 tools on the user MCP door; drafts land, publish/unpublish/delete/review
  decisions return an approval URL; levels per area (Read only, Ask first, Trusted). The pack sits near the door's
  80-tool ceiling.
- **Sessions:** the `.echoofdreams.eu` refresh cookie, so a reader signed in to EoD is signed in on the blog.

## Where Agent Blog already covers it

Posts, revisions with authors, scheduling judged when it fires, tags and categories, RSS, Atom, sitemap, robots,
approval requests as a first-class inbox, agents over MCP with three levels (Full beyond EoD's Trusted), the brief and
owner notes, editing in the app with Approve with edits, notifications to phone/Discord/Slack/ntfy/webhooks, pictures in
R2 with Cloudflare purge, and readers' pages **rendered on the server** (EoD's are a client-side SPA, so its post text
isn't in the HTML search engines and link previews fetch). Most of it was lifted from EoD's blog in the first place.

## The real gaps, and what each needs

| EoD has | Agent Blog | What it would take |
| --- | --- | --- |
| Comments, reactions, Follow, Tip (EoD accounts) | none: comments are a VISION non-goal ("a moderation problem") | **Keep them in EoD.** A theme partial renders an empty `<div data-eod-entity="14" data-id="{post uuid}">` and EoD serves the widget script; the blog stays on `*.echoofdreams.eu`, so the refresh-cookie session works exactly as in blogConsole today. Reading the post needs no JavaScript; commenting does, as now. Keeping post uuids keeps every existing comment and reaction attached. |
| Several human authors (contributor, editor, admin) | one owner; VISION non-goal for v1, seam open ("a post's author is a principal") | Depends on use: if EoD's blog is the owner's devlog, one owner fits and nothing is needed. If staff write, it's a new slice (roles on `blog_member`), close to M5's hosted multi-account work. |
| Sign-in with an EoD account | Google or Discord (agent-kit ProviderSignIn) | The owner signs in with Discord, as on EoD. Readers never sign in to the blog itself (comments happen in EoD's widget). |
| Gallery pictures (`g://`, `gi://{uuid}`) | its own media library | One-time import: fetch each picture from EoD's public image endpoint into the blog's bucket (`upload_media_from_url` does this already) and rewrite the links. |
| TipTap WYSIWYG | Markdown with a live preview | Agents write Markdown; the owner edits on a phone. Fine unless the owner wants WYSIWYG back. |
| Age rules (13–17: no role, no reactions) | not needed | Only applies to EoD's widget, which keeps its own rules. |
| Reports, admin moderation tabs | owner's trash and history | Reports on comments stay in EoD; the posts are the owner's. |
| Echo Guide, notification bell in the shell | none | Out of scope for a blog; links back to EoD. |

## A path

1. **Run an Agent Blog instance for EoD** on Railway, the same shape as blog-ai (Postgres, R2 bucket, Cloudflare in
   front). Its own theme in EoD's look (a fifth Liquid theme), with a creator card linking to the owner's EoD profile.
2. **Import** with a one-off tool: `named_pages` blog posts (keeping each post's uuid, slug, dates, tags, categories,
   the current text and, if wanted, the revision snapshots as revisions), pictures re-hosted, `g://` links rewritten.
3. **Keep the addresses:** EoD's posts live at `/{slug}`, Agent Blog's at `/posts/{slug}`; the blog answers `/{slug}` with
   a 301 (a small, general "old address" table), and `/api/blog/feed.xml` with a 301 to `/feed.xml`. Tag and
   category addresses already match.
4. **Comments widget** served by EoD (ServerAPI already has the endpoints and CORS for blog.echoofdreams.eu).
5. **Switch** the cf-worker's `blog.echoofdreams.eu` route to the new service; then retire `blogConsole`, the
   `blog_authoring` pack (11 tools off a door near its ceiling), the admin blog tabs and the review-queue widget, and
   point `BLOG_URL` consumers (notification links) at the same addresses.

Nothing on EoD's side moves before step 5; the old blog keeps serving until the route flips, and flips back the same way.

## Worth taking from EoD into Agent Blog either way

- **Signed preview links** for an unpublished post (`BlogPreviewLinkSigner`: HMAC, expiring): the owner shares a draft
  with someone. Small, and missing here.
- **OG endpoints per page type** (`/api/og/blog/*`): input for slice 6 (social cards).
- **Reading time, "keep reading", copy link:** theme details, cheap in Liquid.
- **Autosave with conflict** in the editor: the app's editor saves explicitly today.

3. **History:** "start each post's history at the import."
